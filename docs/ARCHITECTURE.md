# Architecture

## Stack

- **Next.js 16 (App Router), React 19, TypeScript strict, Tailwind CSS 4.** Server components for pages, server actions for forms, route handlers for the interactive interview/book APIs.
- **Drizzle ORM** with two drivers behind one interface (`src/db/index.ts`): Neon serverless (WebSocket, transactional) in production and **PGlite** (embedded Postgres) for development, CI and tests. Migrations in `./drizzle` are generated by drizzle-kit and applied by `pnpm db:migrate`.
- **Better Auth** (email + password, Drizzle adapter, cookie cache, account deletion).
- **Anthropic SDK** with structured outputs for every AI operation; **OpenAI / Deepgram** REST for transcription; **Vercel Blob (private)** for recordings; `@react-pdf/renderer` and `docx` for exports.

## Layers (`src/`)

| Layer | Location | Notes |
| --- | --- | --- |
| Presentation | `app/`, `components/` | Design tokens in `app/globals.css`; focus route group for the interview workspace. |
| Auth + authorization | `lib/auth.ts`, `server/session.ts`, `server/authz.ts` | Every project-scoped call resolves `getProjectAccess`; missing and forbidden both become 404. Role permissions are explicit and can only be narrowed by membership grants. |
| Interview orchestration | `server/interviews.ts`, `server/interviewer/*` | Row-locked, idempotent turn appends; planner with coverage model; AI question validated against repetition and avoided topics, template fallback. |
| Speech | `server/media.ts`, `server/storage/*`, `server/transcription/*` | Upload validation (type, size, duration, magic bytes), private storage keys only, transcription adapters, retry, retention. |
| Memory | `server/memory/*` | `pipeline.ts` extracts + reconciles in a transaction; `reconcile.ts` is pure and unit-tested; `service.ts` backs the timeline/people/review UI. |
| Question planning | `server/interviewer/planner.ts` | Bounded context: summary, facts, people, events, open threads, last 14 turns, asked questions. |
| Manuscript | `server/manuscript/service.ts` | Immutable revisions, sources per revision, optimistic concurrency on edits, drafting as a job. |
| Export | `server/export/*` | Book model → PDF / DOCX; project data → JSON. |
| Storage, audit, observability | `server/audit.ts`, `server/logger.ts`, `usage_events` | Logs carry ids, codes, durations and counts only. |
| Conversation Weave (W1) | `server/weave/service.ts`, `app/api/projects/[projectId]/weaves/*`, `components/weave/*` | Behind `WEAVE_ENABLED`. Upload in three steps: reserve (idempotent on `clientUploadId`, fixes the storage key and creates `media_assets` + `weave_recordings`), direct browser upload to private Blob with a client token bound to that path, declared type and size (`handleUpload`, no upload-completed callback), then `complete`, which checks the stored object's size and first bytes before marking it uploaded. Originals are retention-exempt and never overwritten once complete. Playback: 302 to a 5-minute object-scoped presigned URL (Blob) or local Range streaming. |
| Jobs | `server/jobs/*` | `processing_jobs` table; claimed with `FOR UPDATE SKIP LOCKED`; drained by `after()` after responses, by the UI's status polls, and by the cron route. Exponential backoff, stale-lock recovery, idempotency keys. |

## Request flow for an answer

1. `POST /api/projects/:id/sessions/:sid/answers` → same-origin check → session → rate limit → Zod.
2. `submitAnswer` appends the narrator turn inside a transaction (idempotent on `clientTurnId`).
3. A `process_turn` job is enqueued (durable).
4. `planNextQuestion` builds context, asks the AI (if configured), validates, falls back to the template planner, appends the interviewer turn.
5. Response returns both turns; `after()` drains the project's jobs: extraction → reconciliation → summary refresh every three answers → chapter flags.

A failure anywhere after step 2 never loses the answer.

## Deviations from the brief

- **PGlite for dev/tests** instead of a local Postgres server: the sandbox could not open TCP connections, and it makes the test suite hermetic. Production still uses Neon.
- **Private Blob store not provisioned**: the API token available here cannot create Blob stores. The adapter is implemented and tested against an in-memory/local provider; production reports upload as unavailable until a store is attached.
- **Chapter-level source references** rather than character offsets: each revision records the answers it drew on and the drafter's flags quote the specific passage; offsets are left for a later iteration.
- **Remote interviews**: schema (`project_memberships`, `narrator_user_id`, `consent_records.subject_user_id`, session narrator/interviewer ids) and authorization support them; no UI is exposed.
